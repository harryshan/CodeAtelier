## 2. 初版功能边界（已确认）

目标：在本机浏览器中，通过对话完成一个本地项目的代码阅读、修改和验证，并保存历史对话。

| 范围     | 初版包含                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 项目     | 输入或选择本机项目目录；每个会话绑定一个项目，同一项目可建立多个独立对话；UI 按项目分组，项目名称右侧的加号直接建立项目内对话                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 对话     | 多轮交流、流式回复、新建会话、查看历史、在旧会话中继续提问；对于需要多步骤调查、跨文件修改或验证的复杂任务，agent 先读取相关代码和文件并获得足够信息，再自行显示简洁的计划摘要并立即按计划执行，必要时说明实质调整；已完成任务的时间线默认仅显示用户输入和最后一轮 agent 输出，中间过程可按需展开；任务输入框是所见即所得 Markdown 编辑器，输入规则原地转换为富文本并将生成的 Markdown 提交；用户与 agent 消息以安全的 GitHub Flavored Markdown 显示，不执行原始 HTML；当前会话在对话角落提供默认折叠的本地统计，可展开查看服务实报 token、LLM 请求/轮次、工具调用与成功率、任务数量和累计运行时间 |
| 理解代码 | 通过受审批的 `run_command` 使用本机命令列目录、搜索文件名与代码内容；按行读取文件；读取项目 AGENTS.md                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 修改代码 | 通过统一 `edit_files` 批量新建文件或精确修改已有文件、展示修改 diff                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 执行验证 | 执行构建、测试等命令，展示输出和退出状态                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Git 操作 | 通过单一 `git` 工具查看状态、差异、历史、文件和分支；自动暂存/提交指定安全工作区路径，并推送当前分支已配置的安全 upstream                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 权限     | 工作区内普通修改自动执行；危险操作和外部写入需确认，后端落实权限检查                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| 执行控制 | 展示工具执行过程、取消任务、超时与步数限制、明确报告失败                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| 模型配置 | 配置 API 地址、密钥、模型和思考等级（默认 high），首个协议为 Responses，对接用户自建服务                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| 历史保存 | 本地保存消息、工具调用及结果；浏览器关闭或服务重启后可查看                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 平台     | Windows、macOS、Linux；Web UI 与后端默认仅本机访问，可显式开放受信任局域网                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

### 执行限制

- 单 agent；不同真实工作目录的会话可并行执行，默认最多 2 个、设置可调为 1～4 个；同一工作目录始终只运行一个任务，后续任务保持排队。一个会话仍只允许一个运行中或排队中的任务，避免并发追加其上下文。
- 直接修改选定工作目录；不自动创建 worktree，不提供一键回滚。
- 关闭页面后，只要后端仍运行，任务可以继续；重启后端后，将未完成任务标记为中断，不自动重放命令。
- 历史对话可以继续交流，但每次重新执行任务时读取当前文件，不把历史内容当成最新代码。
- 限制工具输出和上下文长度；每次主任务模型请求及重试前按完整历史计量，接近容量时自动压缩会话内旧上下文，保留用户原文、原始历史与恢复状态。无法安全压缩时明确停止。跨会话项目记忆已使用平台数据目录中的 Markdown 文件和本地文本关键词检索：每个任务固定检索 bundle，模型可通过受限 `memory_apply` 自动添加、更新和归档同项目记忆，不等待人工确认；不引入 SQLite/FTS 或向量检索。项目管理 UI、来源失效验证和手工恢复/清空仍待实现，见 memory-system.md。详见 context-management.md（D023、D027）；服务公开容量和实际 token 用量按 D024 接入，未知能力不猜测，详见 model-tokens.md。

### 初版不包含

- 多 agent、子 agent；同一任务内由工具调用 DAG 调度的并行工具执行，以及不同工作目录会话的受限并行任务不属于多 agent。
- 创建 PR、任意未允许的 Git 子命令或选项、指定远程/分支目标、强制推送、重置/清理/检出、合并/变基、标签、stash 或 clone 等 Git 仓库操作；开发本项目时的 Git 同步规则照常执行。
- 浏览器自动化、MCP、插件系统、向量检索。
- 内置完整 IDE、交互式终端、调试器。
- 云端部署、远程访问、多用户账号或账户系统。
- 无人值守的崩溃重启执行；人工恢复已纳入范围（D018）。Windows Sandbox 的后续目标以 [AppContainer Agent Runtime 与 Broker 架构](appcontainer-sandbox.md) 为准：每个 Agent Runtime 使用 AppContainer，完整访问当前工作区和用户显式添加目录，包含 `.git`、`.env` 等全部子路径；全部 Git 在 Runtime 内执行，Broker 不运行 Git。push 逐次确认预期 host/ref 并切换到单用途 Push Runner；Runner 正常加载真实仓库 Git 配置，因而不保证 hooks/helper/配置无副作用。WFP 与认证 relay/CONNECT 代理只强制实际网络不超出获准的精确 HTTPS host，不把预期仓库路径/ref 当作 Sandbox 边界。原生 C++ supervisor 使用受保护控制面、heartbeat/租约和 Job handle；目录 ACL 租约保留原对象 handle/文件 ID，不能按已替换路径撤销。取消/未知结果以区分 Agent Runtime 与 Push Runner 的统一 executionInstance 进入 session，不回滚或重放副作用。该架构尚未实现或验证，能力只能按无网络 Runtime、受限 push、取消/资源三个 profile 分层声明；当前 WSL2 `inspect` 仅是历史实现，见 [sandbox.md](sandbox.md)。

分级诊断日志是同时适用的开发要求（R18）；历史会话与诊断日志分别管理。

## 3. 技术与目录

技术栈、权限细则及默认参数的完整推荐方案见 [technical-proposal.md](technical-proposal.md)。

- 建议 Node.js + TypeScript strict 模式，包管理器已确定为 pnpm，具体版本在实施前固定。
- 建议单包仓库起步；第三方库用于通用基础能力，自研 agent 循环、工具协议、上下文策略和授权机制。
- 已确认采用本机浏览器 Web UI + 本机后端；服务默认仅监听回环地址，用户可显式开放受信任局域网。后端负责模型调用、文件访问和命令执行，前端展示状态并收集用户操作；可由环境变量开启单一密码门禁，但局域网模式不提供多用户账户、权限分级或公网部署。
- 候选边界：API 密钥保留在后端；后端落实权限判断，并校验请求来源和会话身份。具体通信协议与断线处理方案待设计。
- 跨平台实现需处理路径、shell、进程生命周期、文件权限和编码差异；版本与浏览器矩阵确定后安排对应验证。
- 模型层保持小型接口，先落地一种 API 协议，再按实际需要扩展；不预先承诺兼容所有提供商。
- 明确最大步骤、命令超时、上下文容量和重试上限，避免无限循环或无限重试。
- 工具授权是应用逻辑，不能冒充操作系统沙箱。AppContainer/Broker 是 Windows 后续目标设计，不承诺当前可用、跨平台或 Windows 原生系统级隔离；只有通过各阶段真实验收后才可更新能力声明。

模块结构方向（实际目录和职责见 architecture.md）：

```text
src/
  web/          # Web UI、交互、状态展示
  server/       # API、事件传输、会话接入
  agent/        # 循环、停止条件、任务状态
  providers/    # 模型协议适配
  tools/        # 工具定义与实现
  permissions/  # 权限规则与确认流程
  context/      # 上下文构建与预算
  sessions/     # 历史持久化、读取与续聊；中断状态管理
  config/       # 配置加载与校验
tests/          # 按行为组织验证
docs/           # 需求、架构、开发说明和决策
AGENTS.md
README.md
```

依赖方向建议：Web UI 通过 API 与 server 交互，server 调用 agent，agent 依赖工具和模型接口；核心机制不依赖 Web UI。前端不得直接导入文件访问、命令执行或密钥配置模块。共享类型靠近所属模块，避免无边界的 utils 目录。

## 4. Git 工作流与产品 Git 操作

区分两个问题：

- **开发本项目**：建议按文档基线、基础骨架、最小闭环、工具能力等独立可验证增量提交；每个增量同步更新文档。提交语言、Conventional Commits、分支和 PR 策略待定。
- **产品操作用户仓库**：单一 `git` 工具以 action 提供状态、差异、历史、文件查看、分支、暂存、提交和推送。允许动作自动执行，不等待人工审批；写入仅接受明确的安全工作区路径和提交消息，推送仅使用当前分支已配置且经校验的 upstream。产品不支持创建 PR、任意 Git 参数、强推或重置类操作。

## 5. 初版验收标准

- 在测试项目提出“修复一个 bug 并补充测试”：agent 读取项目约定与相关代码、修改文件、运行测试、展示 diff 与结果；需要授权时暂停等待；重启后仍能查看此次对话及工具记录。
- 对循环与工具错误使用可重复的模拟模型测试；真实 API 验证作为单独步骤，不要求所有测试持有密钥。
- 工具失败、模型失败、命令超时和用户取消时能够停止或有界恢复，并报告真实状态及实际错误信息；错误信息在保存、展示和日志记录前必须脱敏、限长。
- 未授权操作被拒绝；路径越界、链接路径和命令执行的边界有明确说明和相应验证。
- 新使用者根据 README 可完成配置并运行示例；敏感配置不会进入版本控制或默认日志。
- 修改模型协议或增加工具时，不需要重写 Web UI 与 agent 主循环。
- 在 Windows、macOS 和 Linux 的约定环境中分别验证安装、启动和编码任务闭环，记录实际验证平台与未覆盖项。
- 在 Web UI 完成任务输入、进度查看、权限确认、diff 查看和取消；刷新或断线时能准确展示任务状态，后端仍运行时任务继续，后端重启后标记中断且不重放命令。
- 验证默认配置下 Web UI 和后端服务仅绑定回环地址；设置 `CODEATELIER_LISTEN_ADDRESS=0.0.0.0` 或 `::` 后可从受信任局域网访问，仍不作为公网服务部署；已配置的模型 API 调用正常工作。
- 保存一段对话后，刷新页面、关闭并重新打开浏览器、重启后端服务，均可在 Web UI 查看已保存的消息，保持原有内容与顺序。此项不要求自动恢复中断的工具执行。

- 日志验收：默认 INFO 时不输出 DEBUG/TRACE；日志文件和终端使用紧凑的格式化纯文本而非 JSON，开启调试后能够通过关联标识追踪一次任务的模型调用、工具执行和失败原因；失败记录包含脱敏、限长的错误消息、受控元数据、原因链和堆栈，不能只留错误类型。各级别日志均不泄露密钥等凭据，长字段受限。实现采用 Pino、平台数据目录和 5 份轮转日志，详见 development.md。

## 6. 实现决定与后续范围

- 采用 Node.js 24、pnpm 11.22.0、React/Vite、Fastify、Node 内置 SQLite、Pino。接口与目录职责见 architecture.md。
- 使用用户自建服务及 Bearer key；本地配置的模型已通过真实流式工具往返验证。
- 权限规则、历史存储、输出限制、日志轮转、配置优先级和启动方式见 development.md。
- 文档中文优先；开发本项目的 commit 使用英文，并按已有规则间隔批量 push。产品 Git 操作仅由 action 和参数受限的单一专用工具自动执行。
- 操作系统和浏览器的实际验证范围见 verification.md；未验证的版本不宣称支持已验证。
- 历史搜索/删除/导出、费用统计、密钥系统凭据库和安装包不属于本次初版必需功能。公开分发前再选许可证。

## 8. 开发评测（D026）

## 可选辅助模型（2026-09-12）

用户要求增加低成本模型配置，供会话标题、工具使用审批、上下文压缩等辅助任务使用。当前实现提供独立模型 ID 和思考等级配置，并接入摘要及首条用户 prompt 的自动标题：新会话先显示“新对话”，标题请求使用辅助模型并在成功后更新历史与 UI；失败保留占位标题且不阻断编码任务，取消会中止任务。空配置下标题与摘要沿用主模型；标题请求没有工具，遇到可重试或无可分类原因的模型调用错误时在首次失败后最多自动重试 3 次。每个原本需要审批的命令或工具使用都会向已配置的低成本辅助模型发送仅含工具名和待审批内容、无工具的 256 token 分类请求，结果为 `approve`、`human review` 或 `reject`：前者自动通过，第二项保持当前人工点击流程，第三项直接拒绝并展示理由。对于 cwd 固定在工作区、只读写工作区文件的常用开发命令，审批 prompt 明确要求直接返回 `approve`，包括包管理器 test/build/lint/typecheck/format 脚本与常见编译、测试、格式化、代码生成命令；写入构建产物或生成文件本身不构成转人工理由。缺少辅助模型、模型故障或无效输出均保守降级为人工确认，不使用主模型代替低成本审批；任何分类都不放宽执行器的既有安全校验。
