# 上下文管理与压缩

状态：已实现会话内压缩；不提供跨会话长期记忆。用户于 2026-09-08 授权实施。

## 工作方式

每个任务先发现服务公开的模型容量。具备已支持的 tokenizer 时，使用 token 输入预算；
否则沿用 settings.contextChars（默认 180000）作为备用字符预算。两种方式均包含 input、instructions、tools。
服务实测数据、预留量和校准规则见 [model-tokens.md](model-tokens.md)。
达到 80% 时尝试整理较早记录，只有压缩后不超过预算 60%，且至少缩小 10%，才提交。
未到 80% 不增加摘要模型调用。

当前应用指令与根 AGENTS.md 每个任务重新加载。被覆盖范围内的用户消息逐条原文保留，
其中包括目标、约束和后续纠正；最近记录保留原文。更早的模型记录变成结构化摘要，
包含 completed、conclusions、verification、pending，每条附本次快照中的原始记录索引。
摘要使用同一个已配置模型，但不提供执行工具；摘要中的指令与授权声明无效。
摘要结构与索引验证不能证明每句话正确，重要结论仍需查原文和当前文件。

切分位置限于没有悬空调用的用户消息之前，或整批工具结果之后；不拆开同批调用与结果。
模型响应中的 reasoning 等协议项随其所在分组保留或归档。
当前批次仍在执行、等待授权或响应接收中不会压缩。恢复任务先使用原有流程补齐已知结果，
没有记录的调用仍标为结果未知，然后才整理上下文。

## 大输出、来源和执行状态

达到触发阈值后逐级尝试，某级达到目标即提交，不继续增加损失或模型调用：

| 级别 | 方法 | 范围与代价 |
| --- | --- | --- |
| 一级 deduplicate | 完全相同的历史文件读取改为引用 | 要求调用参数与完整输出一致、持久化结果唯一匹配；保留第一份全文，不按路径合并版本；零模型调用 |
| 二级 archive | 大文件读取归档，留下路径、行数、首尾和诊断行摘录及来源 | 只处理有已保存成功结果、未截断的 read_file；正文超过 2000 字符才处理；有损活动视图、完整快照可回读；零模型调用 |
| 三级 summary | 完整分块的结构化摘要 | 对旧原始记录分块，不先丢掉中间；此前归档投影按数据库记录匹配并展开全文，再送摘要模型 |

前两级保留调用与结果的协议位置；不投影命令、写操作、失败或未知结果。
二级摘录包含首尾各 400 字符及最多 1000 字符的诊断行片段，显式标注省略；
它是定位线索，不能保证识别所有重要代码或错误。关键词命中不代表程序执行失败。
引用包含 snapshotId、index、offset 与参数/输出的 SHA-256 指纹；回读工具仍按快照索引读取。

三级请求携带原记录索引和字符 offset，长记录按实际预算拆成连续片段，所有片段均送入摘要，
不再固定截取开头 1200/结尾 800 字符。用户原文独立保留，不交给模型改写。
各请求输入与固定指令不超过当前输入预算的 70%。一项任务最多 12 次摘要请求（包含重试），
预估所需调用超限时直接保留旧上下文；不以偷偷省略源材料换取调用次数。
摘要文本最多接受 8000 字符，拒绝非 JSON、结构不符、越界来源和工具调用输出。

本实现生成的旧摘要按数据库中保存的精确内容识别，原文保留并维持原来的来源快照 ID，
不再次摘要。新旧结论按时间并存，不能假定旧验证仍有效。旧版没有 note 字段的快照仍能读取，
但其摘要在升级后第一次压缩时仍按普通历史处理。
保留摘要可能逐渐增长：若用户原文、旧摘要与最近记录已超过目标，停止压缩，
不声称支持无限长会话，也不把旧摘要折叠为可能漂移的新摘要。

没有自动识别“重要代码”的可靠性承诺。摘要可丢失细节，因此提供
read_context_history(snapshotId, index, offset) 只读工具，从当前会话快照分页查原文；
从 offset=0 开始，跟随 nextOffset，null 表示结束。另一会话的快照不能读取。
历史阅读不满足文件编辑所要求的本任务内实际文件读取。

工具执行账本由已保存 tool_result 事件生成，不由摘要模型推断。匹配调用 ID、工具名及完整已保存输出；ID 重用、结果不一致或匹配歧义时保守标为未知。
recorded 只表示存在结果记录，保留 error、exitCode、truncated；unknown 必须先检查现状，
不能推断操作尚未执行，也不能自动重放。连续压缩会继承此前账本。
摘要不会改变 ApprovalManager 或 ToolRunner 的授权与新鲜读取检查。

## 持久化和恢复

SQLite 新增 context_snapshots 表，通过 CREATE TABLE IF NOT EXISTS 兼容现有数据库。
原 events 和 context 表不迁移、不删除；数据库初始化版本标记维持现有值。
每份快照带格式 version=1、父快照 ID、完整压缩前输入、摘要、执行账本、切分索引、
输入 SHA-256、模型、创建时间和压缩前后字符数。新增可选 stage、note、projections 字段，
分别记录提交级别、可核对的摘要原文和可展开的文件投影，兼容旧版快照。
快照和新的活动 context 在同一事务提交；重启可沿父快照追溯之前的摘要来源。

这里的原文是此前已经保存的内容。工具输出原先可能受 outputChars 截断，
压缩机制不能恢复早已被丢弃的输出。快照占用额外磁盘空间，目前不自动清理或设总容量配额。

摘要失败时保留原上下文，并在本任务内停止进一步摘要尝试。
低于硬限制时可以继续；超过硬限制则停止并提供既有人工恢复入口。
规则、用户原文、最近完整分组或继承账本过大时也可能无法压缩，不会偷偷截断用户要求。
人工恢复新建任务，可重新尝试；用户取消和服务关闭会终止摘要请求，不自动重启任务。

服务端明确返回 context_length_exceeded 时，每任务最多强制压缩恢复一次。
恢复后的模型请求仍沿用既有瞬态有界重试；失败的部分输出与新 attempt 分开。
其他 HTTP 400 不推断为容量错误。字符预算无法保证符合未知模型的 token 窗口，
一次恢复也可能失败，需要用户调整容量或开始新会话。

## 操作与诊断

复用现有模型密钥；新增 maxOutputTokens 配置（默认 16384）。启动方式不变：

```sh
pnpm build
pnpm start
```

Web UI“模型与设置”提供“备用上下文字符上限”和“最大输出 token”。字符备用值 180000
不是服务承诺的 token 容量。整理时通过既有 notice 事件显示进度和当前单位的前后大小；
原对话和工具记录继续显示，刷新后仍能查看。内部摘要不作为用户可见的 agent 正式答复。

日志事件：context.compaction_started、context.compaction_completed（INFO）、
context.compaction_failed（WARN），继承 sessionId/taskId，包含前后大小、调用数和成功提交的 stage；通知显示当前计量单位及级别。
不输出摘要正文、历史原文或密钥。现有工具日志记录历史读取工具名与调用 ID。

## 模块和验证

- src/context/context-manager.ts：触发、调用预算、压缩编排与提交。
- src/context/budget.ts：字符预算、保守分组切分。
- src/context/compactor.ts：完整预算分块、摘要模型调用和结构/来源校验。
- src/context/read-projection.ts：可核对的文件读取去重、诊断摘录与归档引用。
- src/context/snapshot.ts、types.ts：执行账本与快照契约。
- src/context/history.ts：会话隔离的有界原文读取工具。
- src/sessions/store.ts：快照查询和原子保存。
- src/agent/engine.ts：安全点接入、通知、容量错误恢复。

tests/context.test.ts 覆盖预算、完整工具批次、用户纠正、重启归档读取、会话隔离、
连续压缩的未知状态、无效摘要、失败退化、事务回滚、取消、过大用户输入、
调用上限、agent 工具往返与容量错误 attempt 隔离。
浏览器用例验证整理提示、正常续聊和刷新后的原历史。
真实模型摘要质量、长期磁盘增长、精确 token 计量和全平台结果不由这些测试证明。
