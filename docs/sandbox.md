# Sandbox 需求与架构设计

状态：S0（开关、模式契约、Broker 安全失败与观测）和 S1（WorkspaceView 策略契约）已实现；Windows 上的 WSL2 bubblewrap `inspect` reference Runtime 已作为部分 S2 实现并完成本机无害夹具验证。它只提供只读工作区命令边界，未完成完整 S2，更不代表 Windows 原生或跨平台系统隔离。本版按 D081、D082、D083 修订 D074：保留真实工作区直接修改，取消任务级 staging、暂存 diff 和合并；外部文件由 Broker 按具体能力读取或写入。

## 1. 目标、开关与兼容性

当前 V1 的路径校验和审批是应用层控制。获准命令以宿主用户权限运行，不能阻止恶意依赖脚本访问工作区外的文件、凭据、网络或进程。后续 sandbox 主要约束**命令及其子进程在工作区之外的权限**，并限制网络、设备和资源；它不保证当前项目免受获准命令修改。

- 由显式环境变量 `CODEATELIER_SANDBOX_ENABLED` 控制启用，未设置或设为 `false` 时关闭。只接受明确的 `true` 或 `false`；非法值在启动时报告配置错误。默认关闭。
- 开关关闭时保持当前 V1 行为完全一致：原有工具契约、审批及辅助模型分流、真实工作区读写、Git、并发、取消、恢复和历史流程均不经过 sandbox broker；不创建隔离 runtime，不增加对现有任务的 sandbox 前置条件。原有安全局限照常说明。
- 开关开启时，所有受其覆盖的命令必须通过已验证的隔离后端。后端不可用、创建或自检失败、执行状态未知时安全失败，绝不暗中退回 V1 宿主权限执行。UI 和历史明确显示本任务的模式；开关不能把旧任务的实际执行方式追认成隔离。
- 开关只在后端启动时读取，运行中改动环境变量不影响既有任务；重启或受监督重载后新任务使用新值。切换时不得自动重放中断任务。

模型服务请求仍由宿主后端发起，模型 API key 不进入 runtime。用户可显式选择的非隔离模式、默认 profile 和各平台最低等级仍需实施前确定；无论产品入口如何设计，都不能把关闭开关的运行显示为已隔离。

## 2. 安全承诺和非目标

- 真实工作区是会话绑定的工作目录。获准可写命令的修改**立即生效**，无需 apply；`edit_files` 继续按现有精确路径、读取版本和审批规则直接修改真实工作区。命令写入不享有 `edit_files` 的逐文件校验。
- 未经单独授权，runtime 不能访问工作区外的宿主文件、环境变量、网络、设备、其他项目、凭据或宿主进程。工作区外实际需求经 broker 按具体文件、操作和调用授予。
- 不提供工作区修改前审核、一键回滚或跨文件事务。命令可以立即删除、改写或重命名当前项目文件；取消、超时及崩溃不会撤销副作用。
- 不承诺抵抗恶意本机管理员、失陷的内核/虚拟化层，或用户批准的外部写入及网络发送。

| 攻击面 | 目标控制 | 剩余风险 |
| --- | --- | --- |
| 不可信仓库与命令 | 无宿主密钥、默认无网络、受限资源的 runtime | 可写命令仍能破坏当前工作区 |
| 路径和链接逃逸 | 后端限制真实工作区视图，不暴露父目录及其他项目 | 工作区内允许的内容仍可被读取 |
| 工作区内 `.env`、`.git` 等 | 一般命令不能直接读取或修改受保护路径；目录列表可能显示名称；Git 走宿主专用工具 | 暂不承诺防护经祖先目录操作或别名间接触及这些对象 |
| 外部读取 | 指定文件单次授权；Broker 读取并限量交给 agent | 内容可进入 agent 上下文、会话历史、后续模型服务请求及 Replay Case |
| 外部写入 | 具体目标和操作单次确认，由宿主专用工具执行 | 已批准写入可能无法回滚 |
| 网络及资源滥用 | 默认无网络、受控目标、进程和资源配额 | 已批准网络目标可收到命令发送的数据 |
| 中断后副作用 | 持久化执行事实，未知结果不重放 | 真实工作区可能已被部分修改 |

不默认支持交互式终端、GUI、Docker/Podman socket、SSH agent、宿主服务 socket、设备、任意端口监听或提权。Sandbox 不改变 UI 入站访问和宿主模型 API 出站连接的边界。

## 3. 组件和能力

```text
Web UI / SSE：模式、隔离等级、工作区写入风险、外部授权
Agent Engine ── PolicyEngine ── ApprovalManager
                         │ 固定工具意图和本次能力
                         ▼
SandboxBroker（宿主可信边界）
  ├─ WorkspaceView：核验真实根目录并提供受限视图与受保护路径拒绝
  ├─ ExternalAccessBroker：外部文件审批、Broker 读取和受限结果交付
  ├─ SandboxManager：后端自检、创建、取消和销毁
  ├─ NetworkBroker：默认拒绝并处理具体目标例外
  ├─ ResultCollector：受限输出、退出事实和资源统计
  └─ ExecutionLedger：阶段和未知副作用记录
                         │
                         ▼
SandboxRuntime：独立、无宿主密钥的命令及子进程树
```

### 3.1 PolicyEngine

现有宿主工具的路径、敏感文件、提权、Git 及人工审批规则继续生效。命令审批生成与任务、工具调用、真实工作区根、后端及有效期绑定的能力。仓库文本、模型建议和工具输出都是数据，不能扩大授权。

| 能力 | 默认 | 授予边界 |
| --- | --- | --- |
| `workspace.read` | 允许 | 只读当前会话的真实工作区视图；直接读取受保护路径被拒绝，名称可能出现在父目录列表 |
| `workspace.write` | 按 profile | 只写当前真实工作区允许范围；直接创建、删除、改名、覆盖受保护路径被拒绝；修改立即生效且 UI 明示 |
| `external.file.read` | 拒绝 | 具体真实普通文件、本次 Broker 读取、读取范围及可见结果范围 |
| `external.file.write` | 拒绝 | 具体目标和操作，经确认由宿主专用工具执行 |
| `network.connect` | 拒绝 | 单次目标、时间和流量范围；可能外传内容 |
| `package-cache.read` | 拒绝 | 经验证的只读缓存，不带用户配置或 token |
| `git.metadata` | 拒绝 | 一般命令不见真实 `.git`；受限 Git 工具独立处理 |
| `privilege`、`device`、`daemon` | 拒绝 | 普通审批不可授予 |

`inspect`（工作区只读）和 `modify`（工作区可写）需分别验证。构建、测试或代码生成实际需要写入时，选明确的可写 profile；只读模式下缓存、临时文件和输出只能落在实例私有目录。不能按命令名称推断只读。外部文件与网络授权默认只对本次调用有效，不跨任务或会话自动继承。

### 3.2 Broker 与外部文件

Broker 是宿主文件、受限 Git、网络例外和进程管理的可信入口。Runtime 不继承父进程环境、任意描述符、宿主工作目录或可请求任意宿主操作的 IPC。通信消息按固定 schema、任务归属、调用 ID、能力和时限验证；runtime 不能要求 broker 代执行任意路径或命令。

1. 审批显示外部目标、规范化真实路径、读写操作、用途、工具调用和范围；并明确读取结果可进入 agent 上下文、会话历史、后续模型服务请求与 Replay Case。整个 home、凭据目录与模糊通配符不作为普通单文件授权。
2. 外部普通文件只由 Broker 在授权后读取。Broker 对实际打开对象核验类型、身份、权限及大小，并按现有读取、脱敏和输出限制把结果交给 agent；不得先检查路径，随后无复核地重新按路径打开。
3. Runtime 和命令不获得外部文件路径、目录映射或原始文件句柄。需要自行按路径、文件描述符或 Windows handle 消费外部文件的通用命令不在本设计的支持范围，应改由 Broker 读取后使用受限宿主工具处理，或明确报告不支持。
4. 外部读取授权允许已获准内容进入完整 Replay Case 捕获，包括工具结果和后续模型请求材料；不因文件来自工作区外而另设 replay 排除规则。既有凭据字段脱敏、受保护本地存储和手动导出规则继续适用。内容也可被 agent 写入工作区、显示在会话历史或用于后续模型请求；审批界面明确提示这些去向。
5. 工作区外写入由现有 `edit_files` 等受限宿主工具在逐次确认后执行，副作用前复核实际目标、类型、版本及操作。命令直接写外部目录不在本设计的普通能力内；如未来需要，须另立高风险设计和验收。

权限检查和实际打开或写入须针对同一对象，或在副作用前重新核验，以防 symlink、junction、reparse point 和并发替换扩大授权。

### 3.3 真实工作区与工具一致性

`run_command`、`read_file`、`edit_files` 和受限 `git` 在同一任务中观察真实工作区。命令修改后，后续工具必须重新读取当前文件；旧 `contentHash` 或历史上下文不是新版本凭证。已知共享资源的同轮 DAG 调用仍须声明依赖，同一真实工作区继续串行排队。命令的写入不是原子操作，不能靠任务锁消除外部进程造成的变化。

工作区视图指向真实目录，不创建待合并副本。后端必须验证工作区外隔离、直接访问受保护路径的读取和修改拒绝，以及链接逃逸；单靠路径字符串过滤或命令黑名单不足。列出父目录时允许看到受保护路径的名称。本阶段不要求阻止经祖先目录改名/删除或硬链接等别名间接触及受保护对象，也不将这些情形计入受保护路径保证；这项剩余风险须在 UI 的隔离说明中可见。命令后展示可观察的真实工作区差异，用于审查**已经发生**的修改，不称为待合并补丁，也不保证捕获全部外部副作用。

### 3.4 Runtime 与平台

每任务建立独立无特权边界、固定 cwd、白名单环境及私有临时目录。不得继承 API key、云凭据、包管理器 token、SSH agent、用户 home、设备或宿主 daemon socket。默认无网络；限制 CPU、内存、进程数、输出和墙钟时间。私有临时目录可按后端能力限制大小，但真实工作区直接写入不承诺目录级磁盘配额；可写命令仍可能消耗承载工作区的宿主卷空间。取消和超时须终止完整子进程树，自检须证明限制实际生效。

当前已确认的默认 profile 是 **`inspect`**。它只读映射真实工作区；需要写入工作区的构建、测试、安装或代码生成命令会失败。Windows 主机的 inspect 命令由 WSL2 Linux Runtime 以 POSIX `/bin/sh -c` 解释，不使用 PowerShell/cmd 语法或 Windows 路径；模型指令必须如实说明该差异。

| 平台 | 候选基线 | 更强候选 | 关键验收 |
| --- | --- | --- | --- |
| Linux | rootless namespace、受限挂载、seccomp/Landlock、cgroup v2 的可验证组合 | KVM/microVM 或受管 VM | 工作区边界、受保护路径、网络、后代进程和 CPU/内存/PID 等可验证资源 |
| Windows | 受限 token/AppContainer、Job Object、受限 ACL 的可验证组合 | 短生命周期 VM | reparse point、网络、全部后代及 CPU/内存等可验证资源 |
| macOS | 受支持、签名且审查过策略的系统隔离 helper | Virtualization Framework 受管 VM | entitlement、共享目录、网络、进程清理及可验证资源 |

等级以行为验收定义，不按组件名称推断。可先完成 Linux 参考后端；Windows、macOS 通过各自真实平台测试后才启用相同等级。无法实施工作区外隔离、受保护路径排除、进程树终止或默认网络拒绝时，相关 profile 不可用且不得静默回退。

当前 Windows 仅注册 WSL2 的 `wsl2-bubblewrap-inspect` 参考后端。它在每次命令前使用 `bwrap` 自检 user/PID/IPC/UTS/network namespace、只读工作区 `/opt`、私有 `/tmp`、`/home`、`/root`、`/run`、`/mnt` 与 `/sys`、新建 `/proc` 和最小 `/dev`，并以 `--clearenv` 清空命令环境。真实 `.git` 遮蔽为私有空目录，现有 `.env`/`.env.*` 映射为空设备：命令不能读取原始内容或写入原路径，但父目录仍可列出名称。WSL、`bwrap`、路径转换或任一自检失败时，Broker 状态回到 `unknown` 并拒绝该命令。它不是 Windows 原生 Runtime，尚无 cgroup/rlimit 资源限制、受控网络例外、外部文件或完整受保护路径别名防护。

## 4. 网络、依赖和 Git

优先使用不带个人配置和凭据的只读依赖缓存。网络默认关闭；确需下载时，审批显示协议、精确目标、端口、期限和流量上限，代理复核 DNS、重定向与目的地址，禁止本机、内网和云元数据目标。域名 allowlist 与字节上限不保证防止向已批准目标发送内容；可区分下载与上传时，对上传单独授权。私有 registry 凭据需另行设计最小权限 broker，不能放进命令环境。

一般 runtime 不见真实 `.git`。宿主专用 Git 工具继续限制 action、路径、revision 和 upstream，禁用 hooks、外部 diff/textconv、pager、编辑器与不必要的 credential helper。可信仓库配置中的 clean/smudge filter、submodule、过滤器和远程行为仍可能带来宿主副作用，必须独立验收；在实现可验证的禁用策略前，不宣称 filters 已被 sandbox 消除。Git 在命令之后查看真实工作区现状；shell 隔离不等于宿主 Git 安全。

## 5. 生命周期、恢复和观测

```text
queued → policy-resolved → provisioning → executing → collecting → completed
                           任一阶段 → cancelled | failed | interrupted | unknown
```

Engine 完成 schema、DAG、审批和真实工作区互斥检查后提交固定意图。Broker 先记录待执行事实，再创建、自检和启动 runtime；记录启动、退出、取消及资源结果。输出经控制字符处理、长度限制和尽力脱敏后进入会话。模式关闭时保持现有生命周期，不强制使用上述新增阶段。

取消、重启或通信丢失后，不自动重放结果未知的命令或宿主写入。人工恢复先确认子进程状态，再检查真实工作区和 Git 状态；已修改文件不回滚。账本保存任务/调用关联 ID、实际后端和等级、能力摘要、阶段、退出或未知结果及外部授权引用，不宣称不可篡改。

新增运行阶段接入 `src/tracing`，覆盖策略、外部授权与 Broker 读取、provision、execute、collect、cancel/destroy、失败及耗时。新增 sandbox span 使用安全摘要，不记录外部文件内容、凭据或完整宿主路径。既有 D069 允许受保护本机 trace 中保存脱敏工具参数；实施时统一字段分类与保留规则，不能宣称所有现有 trace 都不含命令或源码。

UI 显示实际 `sandboxed`、`non-isolated` 或 `unknown` 状态、平台等级、工作区读写能力、外部和网络授权及资源终止原因。可写命令提示修改即时生效且无自动回滚。

## 6. 实施阶段与验收

| 阶段 | 交付物 | 必要证据 |
| --- | --- | --- |
| S0：开关和契约 | 已实现：默认关闭的环境变量、公开模式状态、SandboxBroker 安全失败分流和阶段事件 | 关闭时沿用 V1 宿主命令；开启而无已验证 runtime 时拒绝执行、不回退；配置、Broker、命令分流与 tracing 测试 |
| S1：工作区视图 | 已实现：Broker 规范化真实根目录并向 Runtime 传递 `.env`、`.git` 直接保护契约；当前 WSL2 inspect Runtime 以只读 `/opt` 和启动时遮蔽落实直接路径边界 | WorkspaceView 单元测试覆盖直接受保护目标、名称仍可列出、工作区外链接逃逸和普通路径；本机 Runtime 夹具验证只读工作区和真实 `.git/config` 不可见。仍须补齐并发变化、取消和完整文件系统别名实测；祖先与别名风险继续记录 |

| S3：外部文件 | Broker 受限读取、结果可见范围、专用外部写入 | 对象替换、跨任务隔离、模型/历史/Replay Case 可见性提示及捕获测试 |
| S4：网络和缓存 | 只读缓存、受控代理和单次授权 | DNS/重定向/内网拒绝、上传边界和凭据测试 |
| S5：其他平台与 VM | Windows/macOS adapter、行为自检、可选 VM | 各平台真实路径、进程、网络和权限测试 |

单元测试观察策略与 broker 的外部行为；集成测试使用无害逃逸夹具，记录 OS、后端版本和未覆盖项。不依赖真实模型密钥或用户项目。Evaluation 仍只在用户明确要求时手动执行。

## 7. 实施前待定参数

1. `inspect` 已由用户确认作为开启 Sandbox 的默认 profile；`modify` 的启用条件、显式非隔离模式和任何持久化设置仍待确定；
2. 各平台直接受保护路径规则、最低隔离等级和虚拟化前置条件；祖先与别名防护留待后续单独设计；
3. 外部读取大小、时间与结果可见范围，以及外部写入专用工具的最小操作集；
4. 网络目标、私有依赖凭据、输出、历史及账本的保留与配额。

这些待定参数不改变已确定的边界：**环境变量默认关闭且关闭时保持 V1 行为；启用后无 staging，工作区修改即时生效；工作区外访问逐项授权，命令不获得宽泛宿主权限。**

## 8. WSL2 inspect 实施档案与后续工作

### 8.1 已归档的当前边界

当前后端只在 Windows、显式启用 `CODEATELIER_SANDBOX_ENABLED=true` 且每次自检成功时使用 `wsl2-bubblewrap-inspect`。命令固定以 POSIX `/bin/sh -c` 在 WSL2 中执行，工作区只读映射为 `/opt`；`edit_files` 和受限 `git` 仍是既有宿主真实工作区工具，不受这个 Runtime 隔离。缺少 WSL2、`bwrap`、路径转换或自检任一项时必须安全失败，不回退宿主 shell。

本机证据和精确运行环境记录在 [verification.md](verification.md)。它们只证明该 Windows 主机上的无害夹具，不能替代下列行为验收，也不扩大为其他 WSL 发行版、Linux、macOS 或 Windows 原生实现的承诺。

### 8.2 后续工作档案

以下顺序记录已知缺口，供后续单独设计、实现与验收使用；除“暂缓”说明外，条目均不是自动实施授权。每项完成前，UI、文档和 Runtime 状态继续使用当前实际能力，不以组件名称推断安全等级。

| 优先级 | 后续目标 | 最低验收与失败边界 | 当前状态 |
| --- | --- | --- | --- |
| P0 | 取消、超时、后代进程与 PID 限制 | 用无害 sleep/派生夹具验证取消和超时后没有残留后代；先实测 WSL2 cgroup v2，再决定可验证的 cgroup 或 `prlimit`/`ulimit` 降级；无法证明时拒绝宣称资源或 fork 防护 | 未实现、未验收 |
| P0 | 网络行为验收 | 验证 DNS、TCP、UDP、loopback、宿主/局域网与云元数据均不可达；network namespace 创建或探针失败时 Runtime 必须拒绝执行，不得降级 | namespace 已使用；行为验收未完成 |
| P0 | 文件系统别名和并发变化 | 覆盖 `.env`/`.git` 的符号链接、junction/reparse point、硬链接、祖先目录替换、大小写/Unicode 与运行期对象替换；无法证明的别名不计入保护承诺 | 直接路径和启动时遮蔽已覆盖；别名未完成 |
| P1 | inspect 可用性与诊断 | 记录受控的 WSL/bwrap/内核能力摘要，区分自检、命令自然失败和隔离拒绝；为只读检查设计私有临时目录与不含凭据的只读依赖缓存策略 | 基本自检已实现；体验和缓存未设计 |
| P1 | 真实开发命令兼容性 | 使用无害测试项目验证只读 lint/typecheck/test 场景，并明确哪些工具因工作区只读或缓存写入失败；不将失败命令伪装成隔离故障 | 未验收 |
| P2 | `modify` profile | 先确定隔离写入模型、保护路径、临时空间/配额、可观察差异和恢复语义，再实现；不得把当前 `/opt` 直接改为可写后宣称安全修改 | 未设计、未授权 |
| P2 | 外部文件、网络例外与受限缓存 | 由 Broker 提供精确对象/目标、一次性授权、可见范围和审计；Runtime 不获得宽泛宿主路径、凭据或网络能力 | 未实现 |
| 暂缓 | Windows 原生 Runtime | 不在当前 WSL2 路线中实现 AppContainer、Job Object、受限 token 或 ACL 后端；如未来恢复，须单独设计文件系统、网络、进程树、reparse point 与资源证据 | 用户明确暂缓 |
| 后续 | Linux、macOS 和可选 VM | 分别实现和实机验证；不得从 WSL2 夹具推断其他平台能力 | 未实现 |

后续变更必须同时更新本节、[testing.md](testing.md)、[verification.md](verification.md) 和相关决策；涉及新的执行、取消、资源或 Broker 行为时，也必须接入安全摘要 tracing。
