# 设置系统重设计

状态：2026-10-16 用户授权后已接入实现（D153）。第 1～7 节保留设计背景和验收目标，第 8 节描述当前操作与限制；验证结果见 verification.md。实现不等同用户真实配置已迁移，也不代表全部平台实机验收。

## 1. 改造前的问题

- `src/config/config.ts` 强制从环境读取连接，只保存偏好；UI 输入的主密钥重启即丢失。
- `src/server/app.ts` 在有运行或排队任务时拒绝全部设置修改。
- `src/agent/engine.ts` 虽复制任务设置，后续 provider、审批、MCP 和长工具复查仍可能读取全局密钥或配置。直接取消上述限制会混用新旧配置。
- 服务监听、门禁、Sandbox、tracing、MCP 分散读取环境；`main.ts`、启动命令和 Vite 都有 dotenv 入口。仅改设置弹窗不能完成迁移。

## 2. 唯一配置来源

终态采用“内置默认值 + 宿主数据目录的版本化 settings.json”，不再用产品环境变量覆盖文件。保留系统 PATH、HOME、临时目录等正常运行环境；移除 `.env` 不等于移除全部操作系统环境变量。

文件使用严格 JSON，顶层包含 `schemaVersion`，按职责分组：

- `models.main`：protocol、baseUrl、model、apiKey、reasoningEffort。
- `models.auxiliary`：enabled、protocol、baseUrl、model、apiKey、reasoningEffort；显式展示继承关系。
- `execution`：maxSteps、maxConcurrentTasks、requestTimeoutMs、idleTimeoutMs、outputChars。
- `context`：maxOutputTokens、maxContextTokens、contextChars。
- `sandbox`：enabled、POSIX readRoots/writeRoots、Windows 安装路径高级项。
- `mcp.servers`：沿用现有 stdio/HTTP 字段和校验，最终合入此文件，不保留第二套可覆盖配置。
- `server`：listenAddress、port、访问密码开关及密码验证材料。
- `logging`：level；`tracing`：maxRecords、maxBytes、checkpointMs、retentionDays。

不新增模型连接池、项目级覆盖或任意 provider 参数。模型标识原样传递；Chat Completions/Messages 的能力限制不变。工具不设固定总时限，旧 commandTimeoutMs 只在迁移时消费，不再显示为可调参数。

默认仍用当前平台数据目录；自定义位置建议通过启动参数 `--data-dir` 选择，解决“尚未找到配置就要读取配置位置”的循环。该参数现已接入启动与开发入口。UI 显示实际路径，不提供运行中搬迁 SQLite 的按钮；安装器 Node 路径使用显式安装参数，内部 IPC/构建标记不成为用户设置。

### 凭据建议

建议首版将模型 key 与 MCP 凭据保存在同一个私有 settings.json，避免引入新的配置来源；访问密码仅保存标准密码派生算法生成的加盐验证材料，不保存明文。该存储选择须在实施前明确告知用户，不能把明文 JSON 宣称为加密保险库。

公开 API 使用独立投影，绝不直接序列化磁盘对象。密钥只返回“已配置/未配置”，更新明确区分保留、替换、删除；掩码不是可保存值。MCP headers/env 的既有值同样不回传，URL/参数含凭据时也须受保护。更换端点或协议时要求重新确认凭据，不能把旧 key 自动发往新目标。辅助跨端点或协议不得继承主 key。

文件、临时文件和备份均按敏感资料保护：POSIX 私有权限、Windows 实际 ACL 验证，不以 chmod 宣称 Windows 安全；不提交 Git、不置于默认任务工作区、不投影给 Runtime。应用限制不能抵御具有相同宿主权限的恶意进程。密钥不进入浏览器持久存储、日志、trace、Replay 或错误正文。

## 3. 随时保存，不等于打断当前任务

UI 始终允许编辑、校验和保存；后端标明每项的生效时机：

- **立即生效**：宿主日志级别、全局调度并发上限。降低并发不取消在途任务，只暂停新增启动；同工作区串行不变。已启动 Runtime 的日志级别可保留旧值，UI 不宣称全进程热更新。
- **下一任务生效**：模型连接及 key、思考与请求限制、上下文、输出限制、MCP、每任务 trace 容量。排队任务在实际开始时取最新配置，排队界面明确此规则。
- **重启生效**：监听地址/端口、访问门禁、Sandbox 开关和授权根/安装路径、trace 检查点与归档保留。可先保存，不自动重启、不自动取消任务；涉及删除归档或扩大权限时单独确认。

每个实际启动的任务取得不可变 `TaskConfigSnapshot`，同时固定模型配置、对应密钥、MCP 目录和凭据。标题、审批、摘要、长工具复查及 Broker 模型代理都使用此快照，不再回读可变 Config。Runtime 仅接收必要的无凭据投影。旧任务仍在使用的密钥保持可脱敏，直到相关输出与清理结束。

配置更新不迁移历史。旧会话续聊和人工恢复取新快照；协议不兼容时在执行前明确拒绝，不裁掉不透明历史，不重放未知工具。模型配置变化照常使不兼容 token 锚点失效。

## 4. 保存、冲突与故障

新增配置服务集中管理磁盘目标值、当前有效值和任务快照；公开视图包括配置 revision、待重启字段及字段级错误。

- 保存采用有版本前提的局部更新，不用浏览器旧的全量对象覆盖文件。数组整体替换，MCP 按服务 ID 更新；秘密字段使用独立操作。
- 服务端串行处理保存：严格字段及跨字段校验、检查 revision 和磁盘漂移、私有同目录临时文件、替换成功后发布新内存版本。任一步失败不谎报成功；写入结果不明先重新读取确认，不盲目重试。
- 多标签页冲突返回 409，保留本地草稿，显示非敏感差异供重新应用。不能声称此机制能锁住不合作的外部编辑器；运行中推荐只用 UI 写入。
- 手工编辑文件后使用明确的“重新读取配置”操作，沿用校验及生效规则；不通过文件监听悄悄应用半写文件。发现外部变化先阻止 UI 覆盖。
- 文件缺失可进入初始设置；文件损坏、未知版本或门禁配置无效时不覆盖、不回退成无密码服务，提供本地修复提示。
- 重启前展示任务影响和新访问地址。无监督进程时提示手动重启；失败不自动禁用密码/Sandbox 或切换端口。

接口建议：GET `/api/settings` 返回安全视图；PATCH 同路径携带 expectedRevision、changes、secretChanges；POST `/api/settings/validate` 只校验；POST `/api/settings/reload` 显式重新读取。全部沿用访问门禁、同源校验、写 token 和 no-store；请求体及校验错误不得泄露新输入的 key。旧 PUT 契约需明确退役，不能静默忽略连接修改。

## 5. 完整 UI 设计

按用户追加要求，设置以主页面上的居中模态框展示，不再占满整个页面；复用主页面深色主题、绿色强调色、字体和基础控件。桌面左侧分类导航、右侧独立滚动表单；窄屏保留边缘留白、导航横向滚动，保存栏允许换行且不遮挡表单。原生 dialog 隔离背景交互，关闭恢复焦点与页面滚动；Esc 和关闭按钮均检查未保存草稿，点击遮罩不丢弃草稿。顶栏显示配置位置，保存状态与待重启项保留。

分类与内容：

1. **模型连接**：主/辅助双卡片，协议、地址、完整模型名、密钥状态及替换/删除、思考选项；按协议展示能力，禁用不适用字段。未启用辅助时明确标题/摘要用主模型、审批转人工。
2. **任务与上下文**：并发、轮次、请求/空闲时限、输出与 token/字符预算；显示单位、范围、默认值和生效标签。说明工具无总时限，不创造新研究配额。
3. **Sandbox 与权限**：请求开关与实际执行状态分开；平台相关字段、安装状态、授权根列表和风险说明。保存不执行安装、不提升权限、不改变既有 fallback 和未知实例处理规则。
4. **MCP 服务**：服务列表及编辑抽屉，名称、用途、开关、transport 和对应字段，凭据使用写入控件。保存不连接、不运行命令；本期不增加绕过审批的测试连接入口。
5. **服务与访问**：监听范围、端口、门禁及密码修改；开放 LAN/关闭门禁二次确认，显示重启和重新登录提示。仍仅面向受信任网络，HTTP 不因密码而成为加密传输。
6. **日志与诊断**：日志级别、trace 容量/检查点/保留天数；保留 0 不删除的语义，缩短保留期展示删除影响。
7. **配置与数据**：路径、版本、待生效差异、重新读取、脱敏导出和迁移状态；Skill 预设目录只读说明，不扩展技能市场或数据库迁移功能。

通用交互：切换分类保留草稿；搜索定位字段；保存成功留在当前页；错误定位字段且保留输入；显示“已保存，下次任务生效”而非笼统“已生效”。重启独立按钮再次确认。支持键盘、标签关联、错误焦点和窄屏；密钥草稿仅在页面内存中，离开时清除。

首次启动无需模型配置即可进入回环地址上的设置引导，配置完成前阻止新任务但允许历史查看。没有现存配置时不先开放 LAN；已存在但损坏的配置不能当作首次启动。连接检测不是保存的必要条件，也不自动产生模型费用。

## 6. 迁移与移除 env

实施迁移器时先做只读预检，列出字段来源、冲突、缺失和未知项，不输出凭据。明确选择旧数据目录、dotenv 和 MCP 文件；不扫描任意工作区，也不把 dotenv 当 shell 执行。

迁移连接与服务配置使用明确选定的旧有效环境来源；偏好保留旧 settings 优先级；D065 已忽略的旧连接字段不能复活。进程环境与 dotenv 冲突须报告；仅在旧进程内存中的临时 key 不能假装已迁移。密码转为验证材料，MCP 内容合入新结构。

停写配置并备份原件 → 生成独立候选文件 → 校验完整映射及私有权限 → 用户确认切换 → 在不加载旧环境的进程中验证启动、保存和重启。旧文件不自动删除；核对成功后由用户清理敏感备份与 `.env`。运行中不迁移真实历史库。

终态删除产品启动、Vite、探针和 smoke 脚本对 dotenv 的依赖，替换 `.env.example` 和当前使用文档。遗留产品配置变量只报告名称并拒绝歧义，不长期保留 env 高优先级；系统变量与内部协议标记除外。迁移工具可保留显式读取旧文件的能力，不能变成每次启动的隐式回退。

## 7. 实施顺序与验收

实施按以下依赖顺序推进；当前状态与操作见第 8 节：

1. 配置 schema、私有存储、安全公开视图、并发保存和离线迁移器。
2. 任务完整快照、所有 provider/MCP 调用方及 Runtime 投影，再解除运行中保存限制。
3. 设置 API、初始引导、完整分组 UI 与待生效状态。
4. 服务/Sandbox/tracing 配置接入、受控重启、Vite/launcher/维护脚本统一入口。
5. 无 env 回归通过后更新操作文档和模板，用户另行执行真实迁移。

沿现有 config、server、engine、auxiliary-model、MCP、Runtime 与 Playwright 夹具补测试：空配置启动、错误文件不覆盖、写失败不发布、多标签页冲突、运行中换模型/key 不串用、排队与降并发、辅助凭据隔离、协议不兼容恢复、密码轮换、待重启状态、关闭与端口释放、MCP 保存不连接、迁移重复执行和失败回退、启动及构建不读取真实 env。断言日志/trace/响应无秘密；测试使用临时数据目录和模拟模型，不触碰用户配置。

配置保存/加载/应用记录关联 ID、耗时、字段分类和终态，不记录值。任务 trace 增加安全的配置 revision 关联；无任务的设置 HTTP 操作使用服务日志，不强行归属某任务。跨版本密钥脱敏覆盖到清理结束。实现时同步更新 architecture、development、testing、verification 及平台指南；提交前运行 pnpm check，UI/HTTP 变更另跑 pnpm test:e2e。Evaluation 不自动运行，Windows 单机验证不代表跨平台验收。

## 8. 当前实现与操作

### 新安装与生效

1. `pnpm build` 后运行 `pnpm start`，打开 `http://127.0.0.1:4142`。无需 `.env`，初始设置页引导填写主模型；缺少模型或密钥时禁止启动任务，但可查看历史。
2. 从主页面打开设置模态框，包含模型、任务/上下文、Sandbox、MCP、服务/访问、日志/诊断、配置/数据七类。切换保留草稿；保存携带 revision，冲突保留输入而不自动覆盖。MCP 以服务 ID 更新，秘密明确保留、替换、删除。
3. 默认平台数据目录不变；自定义示例 `pnpm start --data-dir "G:/CodeAtelierData"`。目录不能位于 agent 工作区或授予 Runtime 的根内；不要把凭据配置放进仓库。开发的 `pnpm dev` 与 `pnpm dev:web` 使用相同参数。
4. 日志级别和并发立即调整；模型/key、请求和上下文限制、MCP、trace 容量下一任务生效；监听/门禁、Sandbox、trace 检查点和保留期需要重启。排队任务实际开始时取最新版本，不重新配置已有任务。
5. 密钥、MCP args/env/headers 保存在私有 JSON，**不是加密保险库**。Windows 文件 ACL 仅授予当前宿主用户及 SYSTEM；POSIX 使用私有文件权限。访问密码只保存 scrypt 加盐验证材料。API、导出、日志和 trace 不回显秘密。

### 旧配置离线迁移

以下路径均须替换。先停止旧服务及配置写入；命令不会自动停止服务，不自动删除任何旧文件。

```sh
# 只预检：字段来源/未知字段/环境冲突只报告名称，不输出值
pnpm settings:migrate --data-dir "G:/CodeAtelierData" --env-file "G:/old-app/.env"
# 显式写入私有候选（包含凭据），仍不替换 settings.json
pnpm settings:migrate --data-dir "G:/CodeAtelierData" --env-file "G:/old-app/.env" --write-candidate
# 使用上一条返回的实际候选路径；必须已停止服务
pnpm settings:migrate --data-dir "G:/CodeAtelierData" --apply-candidate "G:/CodeAtelierData/settings.candidate-ID.json" --confirm-stopped
pnpm start --data-dir "G:/CodeAtelierData"
```

迁移器明确读取选定 dotenv、旧偏好及旧 MCP 路径；偏好沿用旧优先级，密码转为验证材料。切换前保留 `settings.json.pre-v1-*.bak` 私有备份，目标已版本化则拒绝重复迁移。候选是生成时的副本：源配置变化后应重新生成候选，不拿旧候选覆盖新设置。启动不隐式回退环境；缺失来源、损坏/未知版本或不安全凭据文件会报错。仅在旧进程内存中的 key 必须重新输入，不能假装迁移成功。

确认无旧环境启动、模型调用、保存和重启正常后，再由用户处理旧 `.env`、MCP 文件、候选及备份；这些文件含敏感资料。此次开发未执行真实迁移、删除或重启。

### 保存失败与边界

- 旧 `PUT /api/settings` 在版本化模式返回退役提示；使用 GET/PATCH、validate、reload 和安全 export。写接口继续使用门禁、同源与 token 校验，响应 no-store。
- 保存采用串行队列、独占 `.write-lock`、私有临时文件与替换前漂移检查。崩溃遗留锁不自动清除；先确认没有其它实例/未知写入，核对磁盘后再人工处理。外部编辑器不受该锁约束，推荐运行中仅用 UI 保存。
- 文件小于等于 1 MiB；损坏配置不覆盖或回退为无密码服务。手工修改后需显式重新读取；结果未知不盲目重放。
- 重启由用户单独确认；有任务时明确中断影响，端口/地址改变后需使用显示的新地址。不会自动安装/Repair Sandbox；实际隔离状态仍以任务结果为准。
- 当前界面以分类导航定位字段，未提供全文字段搜索、自动安装检测或可视化逐字段冲突合并；冲突草稿保留并需用户核对。导出是不可直接替代私有配置的脱敏诊断视图。
- Windows 本次自动化覆盖实际私有 ACL 路径；Linux/macOS 本次未实机验证。真实模型、Sandbox 新安装包和真实旧配置迁移仍需部署环境验证。
