- 决定：模型在同一 Responses 响应的每个工具调用中提供严格的 `{ execution: { id, dependsOn }, arguments }` 信封。Engine 在任一节点执行前校验唯一 ID、依赖引用和无环性，按稳定拓扑顺序调度至多四个已就绪节点；不按工具名称、路径或命令内容推断隐式依赖或锁。旧无信封记录兼容为无依赖节点。
- 失败与恢复：节点失败、拒绝或部分失败时阻断所有后继，并为每个后继保存 `dependency_failed` 结果；独立节点仍可完成。结果与上下文在每个节点结束后立即保存；中断后没有完整结果的节点维持未知，绝不自动重放。
- 原因：模型能把不相关的读取、命令和独立修改放在一个响应中减少往返，同时由显式依赖保留必须串行的副作用。资源冲突推断会产生不透明且不可靠的策略，因此调用计划必须可见、可审核。
- 影响：单 agent、单任务锁仍然成立；DAG 是一个任务内工具执行机制，不引入多 agent 或并行任务。每个工具仍独立经过现有参数、权限和文件快照校验；实际文件写入与工具结果持久化的非原子性边界不改变。

## D067：复杂任务先计划摘要再执行

- 日期：2026-09-17
- 状态：用户要求实现。
- 决定：对于需要多步骤调查、跨文件修改或验证的复杂任务，主任务模型自行采用 plan-and-execute：在首次工具调用前向用户输出简洁的中文 Markdown“计划摘要”，说明目标、有序步骤、预期验证及重要假设或审批边界，再立即按计划执行。证据要求实质改变路径时，先输出修订摘要；简单问答、一次直接读取或琐碎修改不要求单独计划。
- 原因：让用户在复杂编码任务开始时了解 agent 的执行路径，同时不把计划确认变成额外阻塞环节。
- 影响：模型不得要求用户代写或无必要批准计划；已有权限确认仍照常生效。Engine 已先保存并推送同轮文本、后执行其中的工具调用，因此计划与首批工具调用可同轮返回。该提示约束引导模型行为，不取代工具参数、权限、快照、恢复或验证校验。

## D068：按真实工作目录隔离的跨会话并发

- 日期：2026-09-17
- 状态：用户确认并授权实现。
- 决定：保持单 agent，但允许不同真实工作目录的会话同时运行；默认全局上限为 2，可在无运行或排队任务时配置为 1～4。同一真实工作目录始终只有一个运行任务，后续任务以 `queued` 持久化排队；同一会话也只允许一个 queued/running/waiting 任务。
- 原因：用户需要多个 session 同时运行，同时避免共享代码、命令、测试产物和 Git 索引互相干扰。
- 安全与恢复边界：目录锁覆盖读取、编辑、`run_command` 和 Git，不以“只读”推断放宽；排队可取消，服务关闭、重载和重启将 queued/running/waiting 标为 interrupted，不自动重放或自动重新执行。任务以 startedAt 区分实际运行时间与排队等待；不同会话的审批、SSE、取消、模型用量和日志仍按 taskId/sessionId 隔离。
- 影响：替代 D014/D066 中的单任务锁限制，不引入多 agent、worktree、合并机制、用户认证或操作系统级沙箱；并行任务仍会竞争本机和模型服务资源，硬上限为 4。测试覆盖跨目录并行、同目录队列、同会话拒绝、设置互斥及 queued 重启中断。

## D069：本地 Perfetto tracing 与后续功能同步接入

- 日期：2026-09-18
- 状态：用户授权实现。
- 决定：默认启用自研 TraceRecorder，记录任务、上下文准备/压缩、模型请求/退避、响应处理、工具计划、实际工具执行及结果持久化的单调时间线，并导出 Perfetto 可导入的 Chrome Trace Event JSON；Node 主线程执行的上下文、LLM、响应处理、计划和持久化阶段共用 `Main thread`，以 begin/end slice 表达嵌套关系，`Task` 仅作为生命周期包络。工具批次/依赖使用 `Tool scheduler` 逻辑轨道，实际工具仍以最多 4 个可复用并发槽位轨道而非每个 call ID 一行显示。导出按时间排序，flow 用递增整数 ID（而非 UUID）表达模型到工具的因果，且仅保留源操作结束后目标操作开始的边。每个实际 tool span 保存递归脱敏后的完整结构化执行参数；trace 因而可能含命令、路径和编辑文本，只能作为受保护的本机诊断文件，不能上传或提交。任务进入终态后，TraceArchive 将安全 JSON 原子保存为 `traces/<sessionId>/<taskId>.json`，同一会话中每个任务独立保留而不覆盖；无论写入成功或失败，Engine 随即释放该任务的内存记录，不保留完成 trace 缓存。统计框通过本机受保护的会话 trace 清单只显示实际成功保存的任务，本机受保护 API 只下载已落盘文件。
- 数据边界：Perfetto 事件保存关联 ID、模型、步骤、计数、usage、错误类别、状态、耗时及递归凭据脱敏后的工具参数；不保存提示词、模型输出、工具输出、完整服务错误或凭据原文。工具参数可包含源码、命令和路径，扩大了本机 trace 的敏感数据边界；此版本仍不实现高保真 LLM replay payload archive，不能以 trace 重放模型或任何工具，工具恢复的不重放规则不变。
- 长期要求：新增或变更 agent、模型、工具、审批、上下文、存储和跨进程执行等运行时功能时，必须在同一变更评估并接入 tracing，覆盖开始/结束、失败/取消、耗时、关联 ID 与安全摘要。无法合理追踪的例外需要在设计或决策中说明并有测试证据。
- 原因：Perfetto 能直观看到模型、工具 DAG 和后续多进程执行的关键路径，同时保留本机单进程部署、无外部 telemetry 后端和不泄露原始数据的边界。
- 影响：新增 `src/tracing` 与本机只读导出接口；它不替代 Pino 日志、SQLite 会话历史、token 统计或未来独立设计的 replay 存档。

## D070：全量差异与超预算工具上下文保护

- 日期：2026-09-18
- 状态：用户要求实现。
- 决定：模型在当前上下文已经保存完整编辑过程及相关验证时，不轻易请求空路径的全量 `git diff`，优先使用已知变更路径和较小上下文；确有外部变更核对或最终全库审查需要时例外。`git diff` 使用独立的 12000 字符硬输出上限，结果明确标记截断。工具数据与已有材料合并后超过模型输入预算时，下一次主任务请求前必须先压缩；常规三级压缩失败或服务报告容量错误时，使用不调用模型的保底视图。
- 保底边界：完整原文、来源和执行账本原子保存到快照；活动视图保留所有用户原文、最新可见任务结论及尽量多的完整近期记录，裁去中间过程并附历史回读提示。用户输入、结论或必要近期批次本身无法符合预算时明确停止，不暗中删改用户要求或伪造工具结果。

## D071：版本、锚点与唯一空白候选的安全补丁编辑

- 日期：2026-09-18
- 状态：用户确认并授权实现。
- 决定：`read_file` 保留全文字节 `contentHash` 并可选返回可见空白视图；`edit_files` 的已有文件使用该哈希作为 `fileVersion`，并提供可空的前后上下文锚点。编辑先精确匹配，只有普通文件在相同范围内存在唯一“删除空白后相同”的候选时才允许回退；写入仍使用真实原文字符区间。空白敏感文件保持严格匹配，歧义、锚点不符、版本冲突和无候选返回结构化诊断。
- 原因：逐字符 `oldText` 因多一个或少一个空格、CRLF/LF 或缩进差异频繁失败；无边界模糊替换又可能误改重复代码。
- 影响与边界：模型应优先传窄行范围和稳定锚点，读取诊断时使用 `whitespaceMode:true`；不可见字符仅额外显示，不替换可复制原文。不会全文件自动格式化、选择第一个候选、绕过读取版本/路径复核或重放失败/未知写入。工具执行继续产生 tracing span，诊断不把源码写入日志。

## D072：默认全文唯一定位与跨文件类型的换行等价匹配

- 日期：2026-09-17
- 状态：用户确认并授权实现。
- 决定：模型默认将 `edit_files` 的行范围置为 null，使用短而唯一的 `oldText` 在全文定位；重复文本再使用硬行范围或上下文锚点。精确失败后，所有文本文件可在同一搜索范围内用 CRLF/LF 等价关系定位唯一候选；普通文件随后仍可使用 D071 的宽松空白回退。换行等价定位只替换真实字符区间，`newText` 延续匹配片段的统一换行风格；单行片段采用文件的统一风格。
- 原因：当天历史中，多处失败与成功调用的 `oldText` 完全相同而行范围不同；另有只差 CRLF/LF 的失败发生在空白敏感文件。默认窄范围和全禁用空白回退放大了这些可验证的差异。
- 影响与边界：显式行范围仍是硬边界，候选不唯一、版本冲突及其他空白差异仍拒绝；混合换行片段不推断统一风格。离线重放只读历史快照，不代替真实模型 Evaluation。
