- 决定：失败报告必须包含实际错误信息，不能只给出笼统的模型、命令或工具失败说明。模型服务仅从协议错误对象提取 `message`、`reason` 或 `code`，命令启动失败保留子进程错误，非零退出码继续保留 shell stdout/stderr。

## D052：以环境检测的命令替代内置搜索工具

- 日期：2026-09-15
- 状态：用户明确要求实现。
- 决定：移除模型可调用的 `search` 工具及其执行器。每个任务创建模型 instructions 前，在服务进程可见的 PATH 检测常见内容和文件名搜索命令（Windows 对 `findstr` 额外检查系统位置，并在已选中 PowerShell shell 时加入 `Select-String`）；仅注入可用命令名、用途和按通用实现特征估计的性能顺序。模型通过受审批的 `run_command` 使用首个适用工具，并在命令语法支持时合并多个相关关键词。
- 原因：将搜索集中到真实本机环境可用、通常性能更高的命令行工具，避免内置递归搜索的固定限制，并减少逐关键词工具往返。
- 候选范围：内容搜索依次考虑 `rg`、`ugrep`、`ag`、`pt`、`ack`、`grep`、PowerShell `Select-String`、Windows `findstr`；文件名搜索考虑 `fd`、`fdfind` 和 POSIX `find`。排序是推荐，不承诺特定项目上的实测性能或命令在检测后的持续可用。
- 影响：新模型请求不再声明或接受 `search`；`run_command` 仍遵守单次审批、输出限长、直接 Git 拒绝和固定 shell 边界。旧会话的 `search` 事件仍可展示、归档并从快照回读，但不被重放或纳入新版机械去重。

## D053：批量文件编辑独立完成并汇总失败

- 日期：2026-09-15

- 决定：`edit_files` 不因某一个文件的预检、审批、并发变化或写入故障取消其他独立文件；对每个可安全执行的文件继续修改，并在一次结果错误中列出所有失败或结果未知的路径及实际错误。

## D054：低成本模型三级工具审批

- 日期：2026-09-15
- 状态：用户明确要求实现。
- 决定：每个原本需要审批的命令或工具使用，先由已显式配置的低成本辅助模型以无工具、256 token 的请求，严格输出 `approve`、`human review` 或 `reject` 及简洁理由。`approve` 自动通过，`human review` 保留现有人工点击审批，`reject` 直接拒绝并将理由写入工具结果和时间线。
- 原因：让明显低风险操作无需人工逐项放行，同时让明显危险请求在执行前被拦截，保留不确定操作的用户决定权。
- 安全边界：分类请求只含工具名和现有待审批内容，内容被标记为不可信数据；分类模型没有工具，结果不放宽 ToolRunner 的路径、敏感文件、提权、Git、并发或恢复校验。直接被执行器拒绝的操作不调用分类模型。会话授权命中时不重新分类。
- 降级与影响：辅助模型未配置、请求失败、取消以外的异常或不符合严格 JSON 协议的输出，都只降级为 `human review`，绝不改为自动通过，也不使用主模型替代低成本审批。每项分类决定持久化到会话时间线；人工确认卡片显示模型理由。该辅助调用可能增加延迟和模型费用，不保证分类质量或构成操作系统沙箱。
