# 长时间工具运行

命令、Broker 宿主命令、Git action（含 push）与 MCP 操作不再因固定总运行时间而被自动终止。读取/编辑等原本没有总执行期限的工具保持原行为；模型服务商内置的 `web_search` 属于模型请求，不是本地工具进程。

## 每五分钟检查

- 实际执行后每五分钟，由当前主模型发起独立、无工具的状态检查请求。审批、执行槽、Git/MCP 串行队列等待不触发检查；MCP 连接握手仍有独立期限。
- 检查包含任务目标、调用 ID/参数摘要、运行时长、距上次输出时长、输出数量和最新 12000 字符尾部。任务/参数分别最多 6000 字符，已知凭据脱敏。输出截断不阻止尾部继续更新。MCP 提供协议 progress；服务不报告 progress 时显示无新输出，不伪造进度。
- 主模型返回 `continue` 或 `stop` 及简短理由。仅运行久或没有输出不自动视为卡死。慢检查不重叠、不积累；网络/解析等复查失败时工具继续运行，下一周期再查。
- `continue` 不启动新进程、不重放调用；`stop` 只取消当前调用并等待执行器清理。其它并发调用不受影响，主模型随后可以读取工具的中断结果并继续任务。
- 工具完成即移除定时器并取消在途检查，迟到决定不作用于已完成执行。用户停止任务和后端关闭仍传播取消。

不能保证模型一定识别卡死，也不能保证第三方远端服务实际撤回操作。已发生写入不回滚；中断、断连或未知结果必须核对副作用后再决定后续动作，绝不自动重放。

## 设置与兼容

- 不再提供“命令超时”输入。旧 `commandTimeoutMs` 持久化/API 字段仍兼容接收，但统一变为 `0`（无期限）。无需手动调整 settings.json。
- 模型请求总期限/流空闲期限、MCP 配置的 `timeoutMs`（现在仅用于连接握手）、IPC 启动/清理期限仍有效。输出容量、文件 spool 上限、进程树清理与安全限制不变；无时间限制不等于无资源限制。
- Windows Runtime 和 Supervisor 的执行使用 Win32 `INFINITE`，不再有七天墙钟或累计 Job CPU 时间上限；有限探针仍支持有限时限。IPC 升至 v11，旧 Runtime 拒绝握手。更新安装版需先停止任务，按开发指南构建 Runtime/原生程序并以管理员 Repair，然后重启后端；本次开发不会自动执行 Repair。
- 复查使用主模型，不使用低成本审批模型，不增加主循环轮数，但产生额外真实 token 消耗。时间线/会话统计将其列为“工具状态检查”；请求、结果和 usage 进入 Replay Case。它不追加主对话上下文，也不改变续聊 token 校准锚点。

## 实现与诊断

`tools/long-tool-monitor.ts` 管理单调用生命周期和尾部；`agent/tool-review.ts` 负责请求/解析/脱敏。宿主 Engine 注入主模型，Runtime 经认证 IPC 的 `tool_review` 模型用途请求 Broker；宿主命令、Git、MCP 在执行位置各自检查，避免双重监视。

`llm.request` 记录复查开始、终态、耗时、用途与 callId；宿主决定另有 `tool.review_decision`，Runtime 决定在关联 notice 历史中记录。trace 不含输出或模型理由，完整脱敏状态只在模型请求/Replay Case 中可见，仍须保护这些本地敏感数据。

MCP 无期限请求由 `mcp/unlimited-client.ts` 在固定 SDK 的 timeout 设置点适配；有限 timeout 仍交给 SDK，取消和响应/progress 仍由官方协议实现处理。此适配涉及 SDK 私有方法，依赖升级必须重新跑内存协议与真实 stdio 回归，不应未经验证迁移。

自动测试用虚拟时钟验证五分钟周期、多日等待、完成竞争和取消，并以真实本地进程验证输出和清理。不等价于真实模型连续数小时判断、第三方远端取消保证或固定账户安装态验收；macOS/Linux 行为须按各平台实测记录。
